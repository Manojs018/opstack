# Mini ERP + CRM Operations Portal

A complete, working **Mini ERP + CRM Operations Portal** designed for wholesale/distribution companies, used internally by Sales, Warehouse, and Accounts teams. 

This repository is built as a monorepo featuring:
* `/backend` — Express.js + Node + TypeScript + Prisma ORM + PostgreSQL
* `/frontend` — React + Vite + TypeScript + Tailwind CSS + TanStack Query + Axios

## 2. Local Setup & Running

Follow these instructions to run the portal locally on your development machine.

### Prerequisites
* **Node.js** (v18 or higher recommended)
* **PostgreSQL Database** (Either a local PostgreSQL server, a Docker container, or a free-tier **Neon / Supabase** project).

### Step 1: Database Setup
1. Create a PostgreSQL database (e.g. named `minierp_dev`).
2. Obtain your pooled connection string.

### Step 2: Backend Configuration
1. Navigate to `/backend`.
2. Create a `.env` file (copying from `.env.example`):
   ```env
   DATABASE_URL="postgresql://username:password@localhost:5432/minierp_dev"
   JWT_SECRET="your-super-secret-key-change-me"
   PORT=5000
   CORS_ORIGIN="http://localhost:5173"
   ```
3. Install dependencies:
   ```bash
   npm install
   ```
4. Run database setup (this applies the schema and runs the seed script to create demo users):
   ```bash
   npx prisma db push
   npm run seed
   ```

### Step 3: Frontend Configuration
1. Navigate to `/frontend`.
2. Create a `.env.local` file (copying from `.env.example`):
   ```env
   VITE_API_BASE_URL="http://localhost:5000/api"
   ```
3. Install dependencies:
   ```bash
   npm install
   ```

### Step 4: Running the Application
To start both apps, open two terminal windows:

* **Terminal 1: Start Backend**
  ```bash
  cd backend
  npm run dev
  ```
  *(Server runs on `http://localhost:5000`)*

* **Terminal 2: Start Frontend**
  ```bash
  cd frontend
  npm run dev
  ```
  *(Vite app runs on `http://localhost:5173`)*

## 3. Deployment Strategy (Neon + Render + Vercel)

Follow these steps to deploy the application for production use:

### 1. Database (Neon / Supabase)
1. Register a free PostgreSQL database on Neon.
2. Copy the connection string. Ensure it has `?sslmode=require` appended.

### 2. Backend Deploy (Render)
1. Create a new **Web Service** on Render and hook it to your GitHub repository.
2. Configure settings:
   * **Root Directory**: `backend`
   * **Build Command**: `npm install && npx prisma generate && npm run build`
   * **Start Command**: `npm start`
3. Add Environment Variables in Render:
   * `DATABASE_URL`: *(Your Neon Connection String)*
   * `JWT_SECRET`: *(A secure random string)*
   * `PORT`: `5000`
   * `CORS_ORIGIN`: *(Your Vercel URL, set this after Vercel deploy, then redeploy backend)*
4. Run migrations/seeding by using Render's Shell or creating a one-off build task.

### 3. Frontend Deploy (Vercel)
1. Import your repository on Vercel.
2. Configure settings:
   * **Root Directory**: `frontend`
   * **Framework Preset**: `Vite`
3. Add Environment Variables:
   * `VITE_API_BASE_URL`: *(Your deployed Render backend URL, ending with `/api`)*
4. Deploy the frontend, copy the deployment URL, and update `CORS_ORIGIN` in Render.

## 4. Postman API Testing

We have provided a Postman collection at `/postman/collection.json` covering all backend endpoints.
* **Importing**: Open Postman, click **Import**, select `/postman/collection.json`.
* **Variables**: Set the collection variable `base_url` to your backend url (default: `http://localhost:5000/api`).
* **Authentication**: The Login requests automatically store the returned token in an environment variable `jwt_token`, which is attached to all other endpoints in the Bearer Authentication header.

## 5. Core Business Logic Assumptions

* **Stock Levels**: Product stock levels are **strictly read-only** on the products table. Stock quantities can only increase when a **Purchase Order (PO)** is marked as `RECEIVED` (stock-in), and can only decrease when a **Sales Challan** is marked as `DISPATCHED` (stock-out).
* **Inventory Check**: During Sales Challan dispatch, the system verifies available stock for all line items. If any product is short, the transaction is aborted inside a database transaction, and a clear `400` error is returned.
* **Invoices**: Invoices are generated by converting a `DISPATCHED` Sales Challan. The system carries over customer billing details and adds a **18% standard GST tax** onto the subtotal.
* **CRM Follow-ups**: Follow-ups are assigned to specific Sales agents and linked to customers. Pending tasks with a due date in the past are highlighted in red (Overdue) for immediate attention.
* **Role Permissions (RBAC)**:
  * `ADMIN`: Full read/write access across all modules.
  * `SALES`: Manage customers, raise dispatches, add follow-ups. Read-only on stock. No access to invoices.
  * `WAREHOUSE`: Manage products, view/receive POs, dispatch challans. No access to invoices or customers.
  * `ACCOUNTS`: Manage invoices, update billing states, view dispatches/POs, read-only on customers.
